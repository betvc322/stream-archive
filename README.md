# Архив стримов — GitHub Pages

Тёмный каталог фильмов и сериалов с поиском, постерами и настоящими ссылками на записи Boosty. Интерфейс сохранён: компактный список, категории «Все / Фильмы / Сериалы», две сортировки. По умолчанию — **«По алфавиту»**. Кнопки «Мой Boosty», нижнего сообщения о примерах и футера нет.

Эта версия предназначена для **бесплатного GitHub Pages в открытом репозитории**. Next.js App Router собирает готовые HTML/CSS/JS-файлы. GitHub Actions читает Google Таблицу при сборке и публикует `catalog.json` вместе с сайтом. Посетителю достаточно обычного браузера; вход на GitHub не нужен.

## Как работает обновление

1. Вы добавляете запись с гиперссылкой в Google Таблицу.
2. GitHub Actions проверяет таблицу по расписанию каждые 5 минут.
3. Он собирает и публикует обновлённый сайт на GitHub Pages.
4. Открытая вкладка проверяет файл каталога раз в минуту и при возвращении на вкладку.

Google может задерживать обновление опубликованной таблицы, GitHub — запуск задания и доставку новой версии. Поэтому 5 минут — частота проверки, а не гарантированный срок появления записи. Если чтение таблицы завершится ошибкой, публикация остановится; на сайте останется последняя успешная версия.

Данные Google никогда не запрашиваются напрямую из браузера. Серверный `/api/catalog` на GitHub Pages не требуется: его заменяет готовый `catalog.json`. Поэтому не возникают браузерные проблемы CORS. Поиск, фильтры и сортировка работают мгновенно локально, без ожидания GitHub Actions.

## Что нужно сделать один раз

Если проект уже опубликован в вашем аккаунте, этот раздел нужен только для повторной публикации в другом репозитории.

1. На [GitHub](https://github.com/new) создайте **Public**-репозиторий, например `stream-archive`. На GitHub Free репозиторий для Pages должен быть открытым.
2. Загрузите содержимое проекта в корень репозитория: `package.json`, `src`, `public`, `scripts`, **`.github/workflows/pages.yml`** и остальные файлы. Загружать `node_modules`, `.next`, `out` и `.env.local` не нужно. Папку `.github` важно не потерять.
3. Откройте **Settings → Pages**. В разделе **Build and deployment → Source** выберите **GitHub Actions**.
4. Откройте **Actions → Publish catalog → Run workflow → Run workflow**. Если GitHub предложит включить Actions, подтвердите.
5. Дождитесь зелёного результата. Ссылка появится в **Settings → Pages → Visit site** и в задании Deploy.

Адрес проекта обычно имеет вид `https://ВАШ_ЛОГИН.github.io/stream-archive/`. Имя репозитория не нужно прописывать в коде: workflow получает путь из настроек Pages. Для репозитория `ВАШ_ЛОГИН.github.io` или собственного домена корневой путь тоже определяется автоматически.

Не требуются платный сервер, банковская карта, персональные токены, Vercel и аккаунт в другом хостинге. Для работы Actions используется встроенный `GITHUB_TOKEN`. Workflow запускается на стандартных бесплатных Ubuntu-раннерах публичного репозитория; архив сборки хранится один день.

## Подключение вашей Google Таблицы

Откройте файл **[`catalog.config.json`](catalog.config.json)**. В нём уже находится присланная ссылка на опубликованную таблицу:

```json
{
  "publishedSheetUrl": "ССЫЛКА_НА_ОПУБЛИКОВАННУЮ_ТАБЛИЦУ",
  "appsScriptUrl": ""
}
```

В реальном файле вместо пояснения указан настоящий URL. Чтобы заменить таблицу, измените только `publishedSheetUrl` и сохраните файл через Commit changes. Нужна ссылка вида `https://docs.google.com/spreadsheets/d/e/…/pubhtml?gid=0&single=true`, а не адрес редактора с `/edit`.

Чтобы получить публикацию другой таблицы: **Файл → Поделиться → Опубликовать в интернете → нужный лист → веб-страница → Опубликовать**. Включите автоматическое обновление публикации. Публикуйте весь лист либо диапазон **A:D**, чтобы были доступны постеры.

Структура листа:

| Столбец | Что хранить |
| --- | --- |
| A — Фильмы | Название с настоящей гиперссылкой Boosty, например `Ритуал (2017)` |
| B — Сериалы | Название с гиперссылкой, например `Кэрри (2026) 1 сезон` |
| C — Постер фильма | Прямая HTTPS-ссылка на картинку для фильма из A той же строки |
| D — Постер сериала | Прямая HTTPS-ссылка на картинку для сериала из B той же строки |

Первая строка — заголовки «Фильмы» и «Сериалы». Со второй идут записи. Пустые ячейки пропускаются, A и B можно заполнять независимо. Настоящие ссылки, назначенные только части текста ячейки, сохраняются. Например, ссылка только на название сериала и обычный текст «2 сезон» после неё поддерживаются.

Для гиперссылки выделите название и нажмите **Ctrl+K** / **⌘K**. Вся строка с допустимым HTTPS-адресом Boosty открывается в новой вкладке. Строки без ссылки остаются неактивными. При наведении доступная строка подсвечивается и слегка смещает стрелку; при работе с клавиатурой видна рамка фокуса.

Год в скобках и номер сезона отделяются от названия. Числа в названиях «Вышка 2», «Сумерки 2» и «1917» сохраняются. Даты добавления не выдумываются.

Для постера скопируйте именно **адрес изображения**, открывающий картинку без входа, и вставьте его в C или D. Ссылки на страницы фильмов не подходят. Лучше использовать небольшие изображения шириной около 100–200 пикселей. Если URL отсутствует или картинка не загрузилась, показывается нейтральная заглушка. Автоматического поиска постеров на IMDb нет.

Публичный каталог содержит названия, ссылки и адреса картинок. Доступ к самим записям, подпискам и оплате по-прежнему проверяет Boosty.

## Альтернативный источник через Apps Script

Если Google изменит HTML публичной публикации, можно использовать Google Apps Script. Готовый код и пошаговая инструкция находятся в [`google-apps-script/README.md`](google-apps-script/README.md).

После публикации скрипта укажите его настоящий URL `/exec` в `appsScriptUrl` файла `catalog.config.json`. Если заполнены оба адреса, приоритет у Apps Script. При ошибке выбранного источника сайт не подменяется демоданными.

Если оба поля пустые, локальная сборка использует 10 демонстрационных записей без выдуманных ссылок.

## Как принудительно обновить сайт

Откройте репозиторий → **Actions → Publish catalog → Run workflow**. Этим же способом можно повторить сборку после временной ошибки Google.

Чтобы посмотреть причину ошибки: откройте красное выполнение → задание **build** → шаг **Read Google Sheet and build site**. До следующей успешной публикации посетители видят предыдущую версию.

## Чтобы расписание продолжало работать без ручных действий

GitHub может отключать расписания публичных репозиториев после 60 дней отсутствия активности. В workflow предусмотрено автоматическое продление активности: если в репозитории не было коммитов 30 дней, отдельное задание обновляет служебный файл `.github/schedule-keepalive.txt`.

Это не изменяет фильмы, ссылки или интерфейс. Разрешение `contents: write` есть только у этого служебного задания. Коммиты от встроенного `GITHUB_TOKEN` не запускают новый цикл публикаций.

Если вы вручную отключили Actions или запретили автоматические записи в репозиторий, включите их обратно в настройках. В обычном сценарии вручную редактировать код после новых стримов не нужно.

## Локальный запуск и проверки

Установите **Node.js 24 LTS** с [nodejs.org](https://nodejs.org/), откройте терминал в папке проекта:

```bash
npm ci
npm run dev
```

Откройте `http://localhost:3000`. При запуске будет получен свежий каталог. Для смены таблицы достаточно `catalog.config.json`; `.env.local` создавать не требуется.

Проверки и production-сборка:

```bash
npm run check
npm run build
npm start
```

`check` запускает ESLint, TypeScript и тесты. `build` читает таблицу, выполняет статический экспорт Next.js и проверяет наличие каталога и правильность путей всех ресурсов. `start` показывает готовую папку `out` локально; сервер Next.js для неё не нужен.

Для проверки адреса внутри репозитория перед сборкой задайте `NEXT_PUBLIC_BASE_PATH=/stream-archive`. На GitHub эта переменная задаётся автоматически. На Windows в PowerShell переменная задаётся через `$env:NEXT_PUBLIC_BASE_PATH = '/stream-archive'`.

Результат сборки находится в `out/`. В браузерной версии нет ключей Google, токенов GitHub и обращений к ChatGPT. Доступность `github.io` без VPN нужно проверить у нужных российских операторов; это не определяется кодом сайта.

## Основные файлы

- `src/components/catalog.tsx` — поиск, категории и сортировка по алфавиту по умолчанию.
- `src/components/catalog-row.tsx` и `catalog-poster.tsx` — кликабельная строка и постер.
- `src/hooks/use-catalog.ts` — загрузка и обновление статического `catalog.json`.
- `src/lib/published-sheet.ts` — импорт названий, настоящих ссылок и постеров из публикации.
- `src/lib/snapshot.ts` — выбор источника при сборке.
- `src/lib/deployment.ts` — правильные пути ресурсов для GitHub Pages.
- `scripts/sync-catalog.ts` — получение и атомарная запись свежего каталога.
- `scripts/verify-export.mjs` — проверка готовой статической сборки.
- `.github/workflows/pages.yml` — автоматические сборка, публикация и поддержание расписания.
- `catalog.config.json` — единственное обязательное место настройки источника.
